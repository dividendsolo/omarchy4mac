# omarchy4mac

Repo facts for agents and operators: the stack, the commands, the checks, the
dangers, and the behaviour the scripts must keep. Shared rules live in the
global AGENTS.md (`~/code/dotfiles/AGENTS.md`); this file holds only what is
true of this repo. AGENTS.md holds the stack, the commands and the dangers in
short form and points back here.

**Comments:** none, anywhere. The global rule "No comments in code" is checked
by `bin/no-comments` (a copy of agent-stack's `tools/no-comments/`), in the
repo's check step and in `.github/workflows/ci.yml`. Knowledge that a comment
used to carry lives here or in `docs/`, why-history lives in the commit and the
PR, and every workaround is a card.

**What it is.** Omarchy 4, for the Mac. AeroSpace tiles the windows, SketchyBar
takes the bar, JankyBorders draws the borders, Hammerspoon holds the keybinding
overlay, the Omarchy menu, the choosers, the Quake console, the screensaver
clock and the drag-off-the-bar tap, and `bin/theme` themes the terminal, the
editor, the bar and the wallpaper at once from Omarchy's own theme definitions.
Omarchy (`omacom/omarchy`, branch `quattro`) is the reference for every
behaviour; `docs/parity-v4.md` and AUDIT.md score the port against it.

**Stack.** Shell, and everything a Mac runs by default is bash 3.2
(`/bin/bash`): no associative arrays, no `local arr=( <glob> )`, and `${#arr[@]}`
under `set -u` on an empty array is "unbound" — declare the array, then fill it,
and test `${arr:-}` before counting. Python 3 for the parsers and the theme
templates, Swift for `bin/omarchy-video-wallpaper` and the appearance listener,
Lua for Hammerspoon, TOML for AeroSpace and herdr, and a Next.js (Fumadocs)
site under `docs-site/` that Vercel builds from that directory alone: the repo's
other files are not in that upload, so the two pages that come from the repo are
committed there.

## Commands

```sh
install.sh                                  install or update, from a clone or `curl | bash`
install.sh --dry-run                        print what a real run would do, change nothing
uninstall.sh [-h] [--dry-run] [--purge] [--remove-packages]
bin/theme [<name>|random|--list|--sync|--remove <name>|--herdr-sync on|off] [-h]
bin/no-comments                            the comment ban over every tracked file
for t in tests/*-test.sh; do bash "$t" || exit 1; done     the repo's whole check
node docs-site/scripts/sync-content.mjs [--check]
cd docs-site && npm ci && npm run check-content && npm run build
bun tools/no-comments/check.ts --diff origin/main     the ban, on the lines a branch adds
bun tools/no-comments/strip.ts . [paths]              remove comments; name what it cannot
```

`tests/*-test.sh` needs `starship` and `luajit` on PATH (the CI job installs
both). A stub (sketchybar, aerospace, osascript, open, defaults, curl) goes on
PATH with a shebang and a throwaway HOME, so no test touches the running
desktop; `tests/aerospace-test.sh` also reads the live AeroSpace and takes
`ALLOW_ACCORDION="1 2"` for workspaces the user has switched to accordion.
A skipped test is a failure: the checker's `vitest.no-skip.ts` fails the run.

## Dangers

- `~/.local/bin/<name>` is a symlink into the clone, so a script must find its
  own real folder by reading the link, and a helper added under `bin/` has no
  link there until `install.sh` runs again: a `git pull` has to be enough.
- `sketchybar/colors.sh` is generated by `bin/theme` on every switch and is
  gitignored. Never commit it, never read it as source.
- A theme name reaches Lua, AppleScript and file paths. Only letters, digits,
  dot, underscore and dash pass; upstream folder names are not trusted. A path
  goes into a script as one argv element, never into script text.
- Ghostty reads both the macOS app-support config and the XDG one, and which
  wins has bitten before: `theme` writes the same `theme =` line to every
  config it can find.
- Ghostty is never reloaded by signal. SIGUSR2 hung it with sessions open; the
  Hammerspoon watcher clicks Ghostty's own Reload Configuration instead.
- `install.sh` wraps its whole body in `{ }`: under `curl | bash` a command
  that reads stdin (`brew bundle`) would otherwise eat the rest of the script.
- The first `install.sh` run snapshots every setting `theme` rewrites, plus
  `~/.zshrc`, into `~/.local/state/omarchy4mac/originals`. Later runs leave that
  snapshot alone; `uninstall.sh` is the only thing that puts it back.

## Theme pipeline

- `OMARCHY_COMMIT` pins the commit `theme --sync` reads (next to
  `OMARCHY_VERSION`); `OMARCHY_REF` overrides it with a branch or SHA.
- The sync uses one shallow, blobless partial clone, not the GitHub contents
  API: that API allows 60 requests an hour per IP and one sync used 24.
- Sync renders btop, Ghostty and neovim from Omarchy's `default/themed/*.tpl`
  with `{{ key }}`, `{{ key_strip }}`, `{{ key_rgb }}` and `{{ mix a b amount }}`
  against `colors.toml`, the same substitution Omarchy runs at theme-set time.
  `orange` and `brown` are optional upstream and fall back to yellow and muted.
- Backgrounds land as `<theme>_<file>` under `~/Pictures/Wallpapers` so the
  cycler and `bin/omarchy-bg-set` find them by prefix. A theme intro is
  `backgrounds/intros/<stem>.mp4` next to the still.
- `theme random` never repeats the current theme, keeps the last three in
  `~/.config/theme-switcher/recent`, and picks inside the system's light or dark
  bucket. One `mkdir` lock stops two switches from interleaving.
- A switch mirrors to herdr machines only when
  `~/.config/theme-switcher/herdr-sync` exists; `THEME_SYNC_FROM` stops the
  remote from echoing the theme back.
- `theme --remove` deletes the cache entry and writes the name to
  `~/.config/theme-switcher/removed`, which `--sync` skips from then on.

## Desktop behaviour that must not change

- AeroSpace: fullscreen keeps `outer.top`, so it never covers the bar. Five
  workspaces per monitor; `alt-N` is the N-th workspace of the monitor you are
  on (`bin/omarchy-workspace` reads `[workspace-to-monitor-force-assignment]`,
  whose first pattern is a workspace's own monitor). `config-version 2` lists
  the bound workspaces instead of guessing them from the bindings.
- `on-window-detected`: the first rule that matches wins, so the screensaver
  rule stays above the Ghostty rule, and a float rule above a workspace rule
  still moves the window.
- The bar: `sketchybar/plugins/displays.sh` maps the built-in panel's
  DirectDisplayID through `sketchybar --query displays` to an arrangement id.
  Centre items (clock, weather, theme name, sunset, stand-up) draw on the
  external screens only; their right-side copies cover the notched built-in
  panel. Right items lay out right-to-left in add order.
- `theme_name` re-reads on every `sketchybar --reload`, which `theme` fires
  after each switch.
- Floats: every app whose windows open floating, ported from Omarchy's
  `default/hypr/apps/{system,steam,localsend,pip}.conf` — System Settings
  (com.apple.systempreferences), Finder (com.apple.finder), 1Password 8 and 7
  (com.1password.1password, com.agilebits.onepassword7), Bitwarden
  (com.bitwarden.desktop), Raycast (com.raycast.macos), Activity Monitor
  (com.apple.ActivityMonitor), Calculator (com.apple.calculator), Preview
  (com.apple.Preview), VLC (org.videolan.vlc), Steam (com.valvesoftware.steam),
  LocalSend (org.localsend.localsendApp) and the screensaver
  (com.mitchellh.ghostty, the window whose title is org.omarchy.screensaver).
  Picture-in-Picture floats by window title, so it has no app-id.
  `tests/window-fixes-test.sh` reads this list and fails when a float rule is
  missing from it.
- Two launchd agents, templated in `launchd/` with `/Users/YOU` paths that
  `install.sh` rewrites: `com.omarchy-mac.aerospace-keepalive` starts AeroSpace
  at login and relaunches it only on a crash (a clean quit stays quit, and a
  5 s throttle stops a crash loop), after writing the
  `NSStatusItem VisibleCC Item-0` default that guards AeroSpace's
  terminate-on-launch bug when its menu-bar icon is hidden;
  `com.omarchy-mac.theme-appearance` runs the light/dark listener.
- `hammerspoon/init.lua` owns the keys AeroSpace leaves unbound, and the
  testable units are named functions the tests slice out: `consoleFrame`,
  `toggleConsole`, `bindDictation`.
- `sketchybar/icon_map.sh` is upstream Omarchy's icon map. The comment ban
  removed its `### START-OF-ICON-MAP` markers; refresh it from upstream by hand.
- `herdr/config.toml` is ported from Omarchy and symlinked to
  `~/.config/herdr/config.toml`. `theme.name = "terminal"` means herdr draws
  with Ghostty's palette, so a theme switch reaches it with no template.
  Validate with `herdr config check`.

## Generated files and CI

- `docs-site/content/docs/changelog.md` and `parity-checklist.md` are generated
  from CHANGELOG.md and `docs/parity-v4.md`. Edit the source, then run
  `sync-content.mjs`; `--check` (in `tests/docs-content-test.sh`) fails a stale
  page. The first `#` of the source becomes the page title, so the body must not
  repeat it.
- `.github/workflows/ci.yml` runs by hand (`workflow_dispatch`) on the PR
  branch, on a GitHub macOS runner: this repo is public, and the Jog runners
  take private repos only, and its scripts use the Mac's own tools (BSD date).
  The actions are pinned in `actions.lock` and `gh actions-lock --verify` fails
  a workflow that adds an unpinned one. Run
  `vps/scripts/actions-lock.py lock .` in the repo after adding an action.
- Deployment: the docs site is a Vercel project built from `docs-site/`. There
  is no server; everything else runs on the Mac.
